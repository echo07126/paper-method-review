# 论文方法论审查助手 · 软件说明文档

## 1. 产品概述与定位

### 1.1 行业背景与需求痛点
- 高校研究生与科研人员投稿前普遍缺少系统的「方法学自检」环节，常见缺陷（数据划分不清、缺统计检验与置信区间、基线不足、消融缺失、结论外推）往往在审稿阶段才被发现，直接推高退稿率。
- 人工逐条核对方法学清单耗时且依赖经验；通用 AI 写作工具（润色/问答/查重）无法给出**结构化、可定位、可复核**的方法学结论。
- 中文论文与 AI/计算机实证研究缺少趁手的方法学检查工具（现有工具集中于医学报告规范）。

### 1.2 产品定位
- 定位为**作者投稿前的方法学自检辅助工具**（不替代编辑与审稿人决策）。
- 首版聚焦：中文撰写的「计算机 / AI 实证研究」论文（可含英文参考文献与术语）。
- 核心闭环：上传 DOCX → 解析分章 → 清单化审查 → 分级报告（问题/存疑/通过）→ 导出 / 追问 → 修改后复审对比。

### 1.3 目标用户
| 用户 | 场景 | 优先级 |
| --- | --- | --- |
| 研究生 / 科研人员（作者） | 投稿前按方法学清单自检（中文期刊为主） | P0 |
| 导师 / 科研团队 | 快速把关学生论文的研究设计与统计方法 | P1 |
| 期刊编辑 / 审稿人（远期） | 初审阶段方法学问题预筛 | P2 |

### 1.4 差异化优势（与同类产品对比）
| 维度 | 现有工具（医学报告规范类） | 本产品 |
| --- | --- | --- |
| 代表 | PAT（CONSORT/STROBE/TRIPOD 清单核对）、Methods Section Sanity Checker（浏览器扩展）、StickForStats（假设检验校验）、Aperivue/medsci-skills（32 条 EQUATOR 指南） | 论文方法论审查助手 |
| 检查方式 | 以「报告清单是否提及」为主 | **确定性规则 + 模型顾问**双层判定，规则给出可复现结论 |
| 定位精度 | 多为条目级提示 | **按章节定位到原文段落**，点击跳转、可复核 |
| 覆盖对象 | 医学 / 生物医学报告规范 | **计算机 / AI 实证研究**（数据划分、基线、消融、统计检验、多重比较、可复现性） |
| 学科扩展 | 版本迭代快但集中在医学 | 解析器 / 清单 / 模型 / 导出四类接口可插拔，便于扩展学科与格式 |
| 输出 | 清单勾选或提示 | 分级报告（严重/中等/轻微/存疑/通过）+ 修改建议 + 导出 + 修改前后对比 |

### 1.5 合规与知识产权
- 论文数据由使用者自备；演示与评测使用**自建样本 + 开放许可（CC-BY）论文改写样本**，来源与许可在 `samples/ground_truth/*.json` 中逐条记录。
- 第三方依赖与模型许可：Python 依赖（FastAPI/Pydantic/python-docx 等）与 DeepSeek API 均遵循其许可与使用条款；前端依赖为开源许可。
- 隐私：论文内容仅在本次审查中发送至模型服务商，不用于训练；服务端**仅在本次会话内暂存**正文（随机文件名的临时目录 + 结构化解析结果），可一键删除，会话过期或服务重启后自动清除（详见 4.5 安全与合规）。

## 2. 技术架构与创新

### 2.1 总体架构
```
┌────────────── 前端（Vue3 + TS）──────────────┐
│ 上传/解析预览 │ 审查报告 │ 原文定位 │ 修改对比 │ 追问 │
└──────────────┬───────────────────────────────┘
               │ REST（HttpOnly 会话 Cookie）
┌──────────────▼───────────────────────────────┐
│               后端（FastAPI）                  │
│  上传校验 → 解析(DOCX) → 审查编排 → 报告/导出   │
└──────┬────────────┬─────────────┬─────────────┘
       │            │             │
 ┌─────▼─────┐ ┌────▼─────┐ ┌─────▼──────┐
 │ 文档理解   │ │ 审查引擎  │ │ 报告引擎    │
 │ 解析/分章  │ │ 规则+模型 │ │ 分级/导出   │
 └─────┬─────┘ └────┬─────┘ └────────────┘
       │            │
 ┌─────▼────────────▼─────┐      ┌──────────────────────┐
 │ SQLite（会话/报告）      │      │ LLM Provider（可插拔）│
 │ 临时目录（上传件，自动清理）│      │ DeepSeek Flash API   │
 └────────────────────────┘      └──────────────────────┘
```

### 2.2 模块与数据流
- 三引擎解耦：**文档理解引擎**（解析 → 章节切分 → 要素抽取，产出 `DocumentIR`）→ **审查引擎**（规则引擎 problem/pass + 模型顾问 存疑/建议 + 证据门控）→ **报告引擎**（Finding 汇总 → 分级统计 → 导出/交互）。
- 对象分层（Pydantic）：结构层（Document/Section/Paragraph/Sentence + 锚点）→ 引用层（CitationMarker/ReferenceEntry，上标角标与文献表对账）→ 知识层（ReviewItem，17 条清单，外部 JSON 可插拔）→ 证据层（Element，21 类方法学要素）→ 判定层（Finding/ReviewReport，含锚点与来源版本）。

### 2.3 AI 技术选型依据
| 需求 | 选型 | 理由 |
| --- | --- | --- |
| 结构化输出稳定性 | Pydantic + JSON Schema 校验 + 失败重试 | 模型输出必须可机读、可校验，非法条目丢弃并记录 |
| 判定可复现 | 规则引擎（确定性）为主 | 规则零 token、可单测、结果稳定；避免"全靠模型"的波动 |
| 开放语义判断 | DeepSeek Flash（顾问模式） | 语义类问题（设计-统计匹配、指标匹配、结论外推）由模型给建议，进入「存疑」供人工复核 |
| 论文类型适配 | 关键词+计数启发式分类 | 综述/理论论文自动跳过 13 条实证类检查，避免系统性误报 |
| 成本与延迟 | 模型分批调用 + 并发限制 | 单篇 1–2 次调用、约 10–40 秒、¥0.01–0.05 |

### 2.4 创新点
1. **规则 + 模型双层判定**：规则负责可复现的确定性问题（问题判定），模型负责开放语义建议（存疑），并通过**规则前置否决**（规则判"通过"时模型不得报问题）保证精确率。
2. **证据门控与引用落地验证**：模型结论必须挂到原文要素锚点，或逐字引用可在原文匹配的句子，否则降级为「存疑」，抑制幻觉。
3. **可追溯报告**：每条问题带章节级锚点，点击跳转原文、支持修改前后对比，形成"发现→定位→修改→复测"闭环。
4. **论文类型与适用性守卫**：自动区分综述/理论 vs 实证，避免对非实证论文误报；问卷、纯生物实验类样本不会触发模型类检查。
5. **可插拔架构**：解析器 / 清单 / 模型供应商 / 导出器四类接口，新增学科或格式不改主流程。

## 3. 功能设计与实现

### 3.1 核心功能与「AI 在哪个环节」
| 功能 | 说明 | AI/算法环节 |
| --- | --- | --- |
| 文档上传与解析 | DOCX 上传；标题样式 + 版式启发式识别章节；上标角标与文末文献对账；表格结构化解析（二维网格 + 题注 + 文档流锚点）；OMML 公式文本提取；图片计数与提示 | 规则/版面启发式：章节识别、角标提取、文献编号对账 |
| 方法学要素抽取 | 21 类要素（样本量、数据划分、统计检验、p 值、置信区间、效应量、基线、消融、超参数、预处理、可复现性、局限、多重比较、重复实验、结论、外推、创新模块等） | 中英双语词表 + 句子级匹配（确定性），全部带原文锚点 |
| 逐条审查判定 | 17 条清单逐条给出 通过/问题/未适用 + 严重级 + 描述 + 原文引用 + 修改建议 | **规则引擎**（确定性规则函数）+ **模型顾问**（语义类建议，进「存疑」） |
| 全局一致性检查 | 跨章节矛盾（如"在测试集上调参""未给出划分比例与种子""结论外推"） | 规则引擎的多条件组合与上下文判定 |
| 报告与定位 | 分级统计、按严重级/存疑/通过筛选、点击定位原文、导出 Markdown | 报告引擎（Finding 渲染 + 锚点跳转） |
| 修改前后对比 | 同一论文两版报告对比（已解决/保留/新增） | 报告差异计算（按清单条目 ID） |
| 单条问题答疑 / 自由提问 | 对某条问题追问"怎么改"，或在报告页自由提问；支持多轮上下文（最近 10 轮 / 8000 字符） | 模型自由文本调用；无 Key 时降级为规则模板回复 |
| 图表一致性检查 | 附加条目 `R-FIG-01`：图/表缺题注、正文引用无对应题注、题注与正文样本量矛盾；`R-FIG-02`：视觉识读图内数值线索（列为「存疑」） | 纯文本题注-引用对账 + 多模态视觉识读（Provider 不变） |
| 论文类型识别 | 综述/理论 vs 实证 vs 未知；综述仅执行通用条目 | 关键词 + 计数启发式（强信号优先） |

### 3.2 辅助功能
- 免登录访客体验（匿名会话）、一键删除会话数据（DB + 临时文件）。
- 报告历史：当前会话内按论文名筛选、问题分布概览、时间排序、查看与导出；报告随会话过期自动清除，历史页对已清除报告给出明确提示并引导切换。
- 解析质量提示：启发式标题数、内嵌图片数、表格行数、是否识别到参考文献区。
- LLM 降级：未配置 Key / 调用失败 / 输出非法 → 退回规则结果并给出中文提示。
- 图表防护：表格结构化解析（二维网格）并纳入表体要素审查；内嵌图片落盘（会话目录内）并由视觉模型识读图内数值、以「存疑」线索回填；规则模式不消费图内数据，可选保守模式（把可能依赖图像证据的条目降级为「存疑」）。

### 3.3 扩展性设计（模型升级 / 多技术融合）
| 扩展点 | 接口/机制 | 现状与后续 |
| --- | --- | --- |
| 文档格式 | `DocumentParser` 协议 + 能力位（页码/上标/坐标/表格/OCR）+ 注册表 | 一期 DOCX；PDF 二期；OCR 三期 |
| 审查清单/模板 | 外部 JSON + Pydantic 校验 + 模板过滤 | 17 条；可扩至 40+，新增条目不改主流程 |

| 多技术融合 | 规则 + 模型 + 版面启发式 + 词表 | 后续可接向量检索（证据召回）、视觉模型（图表识读） |

def classify(document: DocumentIR) -> tuple[str, dict]:
    text = "\n".join(p.text for p in document.paragraphs)
    titles = " ".join(s.title for s in document.sections[:5])
    review_hits = len(REVIEW_SIGNAL.findall(text))
    strong_hits = len(STRONG_REVIEW_SIGNAL.findall(text))
    empirical_hits = len(EMPIRICAL_SIGNAL.findall(text))
    if STRONG_REVIEW_SIGNAL.search(titles) or strong_hits >= 2 or (review_hits >= 3 and empirical_hits <= review_hits):

    return ("empirical" if empirical_hits >= 3 else "unknown"), {...}

### 4.5 安全与合规（要点）
- 上传：扩展名 + 魔数 + 大小 + 页数 + 压缩炸弹校验；随机文件名、Web 根之外落盘。
- 会话与越权：匿名会话令牌（仅存哈希）；按 ID 读取强制会话条件，跨会话 404。
- 数据外发：调用模型前在界面明示"内容将发送至大模型服务商，仅用于本次审查、不作为训练数据"；正文仅在会话内暂存、可一键删除；日志脱敏。
- 生产守卫：非 dev 环境禁止 DEBUG 与公开 API Docs；CORS 通配符与凭据不可同用；限流（上传 20/min、审查 10/min、追问 120/min，会话+IP 双桶）。
- 33 项安全控制点全部已实现（上传校验、越权防护、限流、密钥服务端化、日志脱敏、生产配置守卫、非 root 容器、CI 依赖扫描、追问历史纳入删除链、图片落盘在会话目录内）。

### 5.2 市场分析
- **用户规模**：国内在读研究生与科研人员体量庞大，"投稿前自检/导师把关"是高频刚需；现有 AI 写作工具聚焦语言润色与查重，方法学审查属空白。
- **竞品格局**：现有同类工具集中在医学报告规范（PAT、Methods Section Sanity Checker、StickForStats、Aperivue/medsci-skills），以"报告清单是否提及"为主；面向**计算机/AI 实证研究**、且**按章节定位 + 可复现规则**的产品几乎没有。
- **价值路径**：面向个人的按次/订阅；面向高校图书馆、科研管理部门与期刊社的服务；与写作/投稿工具集成（提供审查 API）。

### 5.3 成果总结
- **可运行产品**：前端四页动线（上传 → 解析预览 → 审查报告 → 修改对比）+ 追问/自由提问（多轮上下文）；后端 10 个接口；支持本地与容器两种部署形态。
- **核心资产**：17 条审查清单、21 类方法学要素、规则引擎（含上下文判定与适用性守卫）、论文类型识别、章节级锚点定位、证据门控与引用落地验证、Markdown 导出。
- **质量证据**：评测集 82/82 = 100% 检出、精确率 100%、定位 96%；4 篇用户盲测（含预埋 16 条缺陷论文 14/14 检出）；单元测试 96 项全绿；安全核查 33/33；接口契约测试通过。

### 5.4 不足与未来规划
| 不足 | 说明 | 规划 |
| --- | --- | --- |
| 仅支持 DOCX | PDF 版面与坐标未实现（接口已预留） | 二期：PDF 解析 + 页码/坐标高亮；三期：OCR 扫描件 |
| 图像内数据 | 图内数值由视觉识读产出**存疑线索**（表格已结构化解析；规则模式不消费图内数据） | 提升识读精度与图-文自动核对（L2/L3 联动） |
| 语义类问题依赖模型建议 | 进入「存疑」供人工复核 | 持续用真实样本回归；必要时微调/换模型 |
| 单机架构 | SQLite + 进程内限流 | 上云多实例前引入共享存储与网关限流 |
| 清单以 AI 实证为主 | 学科覆盖有限 | 按学科模板扩展至 40+ 条，引入领域评审 |
