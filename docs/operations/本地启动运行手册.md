# 本地启动运行手册（v1.0，2026-09-25）

> 面向**在本机把前后端跑起来自己看效果**的人。目标：从零到能打开页面，全程可复制粘贴，每步都有验收标准。
> 生产环境（公网服务器）请改用 `docs/operations/生产部署启动手册.md`。

## 0. 先看：本地形态长什么样

| 组件 | 地址 | 说明 |
| --- | --- | --- |
| 前端（Vite 开发服务器） | <http://localhost:5173/> | 页面入口；`/api` 请求由 Vite 代理到后端 |
| 后端（Uvicorn） | <http://127.0.0.1:8000> | FastAPI；健康检查 `/api/v1/health` |
| 交互式接口文档 | <http://127.0.0.1:8000/docs> | 仅 `DOCS_ENABLED=true` 时开放（本地默认开） |

两个进程**必须同时运行**：前端只做页面与代理，所有解析、审查、追问都在后端。

```
浏览器 → :5173 (Vite) → /api/* 代理 → :8000 (FastAPI) → data/app.db + data/tmp/
```

## 2. 首次准备（只做一次）

### 2.1 进入项目根目录

所有命令默认在**项目根**执行，除非显式标注 `cd backend` / `cd frontend`：

```powershell
cd <项目根>/paper-method-review
```

### 2.2 创建虚拟环境并安装后端依赖

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # macOS / Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
```

> 若 PowerShell 报「禁止运行脚本」，先执行一次
> `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`，再重新激活。

### 2.3 生成配置文件

```powershell
Copy-Item backend\.env.example backend\.env
```

`backend\.env` **是本地唯一真实配置来源**（优先级：显式入参 > `backend/.env` > 系统环境变量 > secrets）。若不创建该文件，`Settings` 会回落到代码内默认值，`CHECKLIST_DIR` 等相对路径可能失效。

### 2.4 填写 API Key（可选但推荐）

编辑 [backend/.env](file:///d:/Users/echo/Documents/2026-09-06/https-www-aicomp-cn-tracks-tracks/paper-method-review/backend/.env)：

```ini
DEEPSEEK_API_KEY=sk-你的Key
DEEPSEEK_MODEL=deepseek-flash
```

| 是否配 Key | 影响 |
| --- | --- |
| 已配置 | 规则判定 + 模型顾问（语义建议进「存疑」）+ L3 图像视觉识读均可用 |
| 未配置 | **纯规则模式**仍完整可用（82/82 检出、100% 精确率口径即出自规则模式），追问退化为规则模板回复 |

**不配 Key 也能验证绝大部分功能**，这是本项目「规则优先、模型增强」设计的直接体现。

### 2.5 安装前端依赖

```powershell
cd frontend
npm ci
cd ..
```

## 3. 日常启动（每次开发）

需要**两个终端**。后端先起，前端后起。

### 3.1 终端 A：启动后端

```powershell
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

看到以下三行即为成功：

```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

> 注意 `cd backend` 后在**该目录内**执行 `app.main:app`。若从项目根启动，模块路径要写成 `backend.app.main:app`，但此时 `CHECKLIST_DIR=../checklists` 会解析错误，**不推荐**。

**验收**（另开一个终端）：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
# 期望：status=ok  app_env=dev  docs_enabled=True
```

### 3.2 终端 B：启动前端

```powershell
cd frontend
npm run dev
```

看到以下输出即为成功：

```
VITE v7.3.6  ready in 712 ms
➜  Local:   http://localhost:5173/
```

**验收**：浏览器打开 <http://localhost:5173/>，能看到上传页。

### 3.3 停止服务

在各自终端按 `Ctrl+C`，或直接关闭终端。

> 关闭后 `data/tmp/` 下的临时文件会在下次启动时由 `cleanup_expired` 自动回收（启动清理 + 每 5 分钟轮询）。

## 4. 配置项速查（`backend/.env`）

改动后**必须重启后端**才生效。

### 4.1 常用开关

| 配置项 | 默认 | 作用 |
| --- | --- | --- |
| `APP_ENV` | `dev` | 本地保持 `dev`（`prod` 会强制关闭 DEBUG/API Docs 并在不合规时启动即报错） |
| `DEBUG` / `DOCS_ENABLED` | `true` | 本地可开；`dev` 环境不受生产守卫限制 |
| `LLM_DEFAULT_ENABLED` | `true` | 审查页「启用模型顾问」复选框的默认值 |
| `LLM_ADVISORY_ONLY` | `true` | **顾问模式**：模型结论一律降级为「存疑」，不计入问题数 |
| `DEMOTE_ON_FIGURES` | `false` | 图表保守模式的默认值（页面可勾选覆盖） |
| `LLM_VISION_ENABLED` | `true` | L3 图像内容识读总开关 |
| `LLM_VISION_MAX_IMAGES` | `4` | 单篇最多识读几张图（按张计费，控制成本） |
| `CHAT_HISTORY_MAX_TURNS` | `10` | 追问上下文轮数上限（1 轮 = user + assistant） |
| `CHAT_HISTORY_MAX_CHARS` | `8000` | 追问历史总字符上限（含 system，超出整轮截断） |

### 4.2 限制与留存

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `MAX_UPLOAD_MB` | `50` | 上传大小上限；同时受解压体积（300MB）与压缩比（120×）防护约束 |
| `MAX_PAGES` | `60` | 页数上限（读 `docProps/app.xml`） |
| `SESSION_TTL_HOURS` | `2` | 会话有效期；过期后报告不可访问 |
| `DATA_RETENTION_HOURS` | `2` | 数据保留期下限，实际取 `max(TTL, 本值)` |
| `DB_PATH` | `./data/app.db` | SQLite 路径（相对 `backend/`） |
| `TEMP_DIR` | `./data/tmp` | 上传件与内嵌图片目录（相对 `backend/`） |
| `CHECKLIST_DIR` | `../checklists` | 审查清单目录（相对 `backend/`，故需在 `backend/` 内启动） |

### 4.3 限流

上传 20/min、审查 10/min、只读与追问 120/min（会话 + IP 双桶，超限返回 429）。本地频繁联调可临时调大 `RATE_LIMIT_*`。

## 5. 上手体验路径（建议顺序）

按这条路径走一遍，能把一期与二期的能力都看到。

### 5.1 准备素材

仓库自带 16 篇评测样本，推荐这几篇：

| 样本 | 特点 | 能验证什么 |
| --- | --- | --- |
| `samples/real/blind-003.docx` | 4 表 2 图、统计量齐全 | **二期效果最集中**：表格渲染、图表一致性、图像识读 |
| `samples/real/blind-004.docx` | 预埋 14 条缺陷 | 问题检出与原文定位 |
| `samples/real/real-003.docx` | 图片 + 表格并存 | 图表引用与题注排查 |
| `samples/fixtures/synthetic-001.docx` | 5 段极简夹具 | 快速跑通、看报告结构 |

### 5.2 走一遍主流程

1. **上传页**：选 `blind-003.docx` → 上传。注意隐私说明与解析质量提示（启发式标题数、内嵌图片数、表格行数）。
2. **解析预览**：看章节列表；两个选项——「启用模型顾问」（默认勾选，产生 token 消耗）、「图表未解析时保守处理」。
3. **开始结构化审查** → 自动跳报告页。
4. **报告页**重点看：
   - 表格是否按二维网格渲染（一期只显示为普通文本行）；
   - 是否出现 `R-FIG-01` 图表一致性条目（题注缺失 / 引用无对应题注 / 样本量矛盾）；
   - 若启用了模型顾问，是否出现 `R-FIG-02` 图内数值「存疑」线索；
   - 点任一问题 → 右侧原文高亮定位到对应段落。
5. **追问 / 自由提问**：点「追问这条」或「自由提问」，连问两轮（如先问「这句该怎么改？」再问「有推荐的写法吗？」），观察后端是否记住上文；若触发上限，抽屉会提示「上下文已达上限」。
6. **修改对比页**：对同一篇的初稿/修改稿两份报告做对比（需先各审一次）。
7. **报告历史**：查看当前会话的报告列表，支持按论文名筛选与导出。
8. **导出 Markdown**：报告页右上角链接。

### 5.3 值得刻意观察的两个设计点

- **顾问模式**：模型给出的语义建议永远落在「存疑」区，问题判定只由规则给出。这保证同一篇论文重复审查结果稳定。
- **降级不报错**：把 `DEEPSEEK_API_KEY` 清空重启，全流程仍能跑完，模型相关条目退化为「存疑」或模板回复。

## 6. 本地自测命令

均在项目根执行（脚本内部会自行 `sys.path` 修正）。

### 6.1 全量门禁（提交前跑一遍）

```powershell
python -m pytest backend/tests -q --basetemp=../.pytest-tmp
python backend/scripts/eval_ac.py
python backend/scripts/security_audit.py
python backend/scripts/api_check.py
```

| 脚本 | 期望结果 | 作用 |
| --- | --- | --- |
| `pytest` | **69 passed** | 单元 + 契约测试 |
| `eval_ac.py` | **82/82 = 100% 检出、精确率 100%、定位 96%** | 评测集指标唯一口径 |
| `security_audit.py` | **33/33**，失败返回 1 | 安全控制点逐项取证 |
| `api_check.py` | `API CHECK PASS` | 端到端冒烟（上传→审查→追问→越权→清理），并自证未写入真实 `data/` |

> **Windows 必须加 `--basetemp=../.pytest-tmp`**：pytest 默认临时目录在部分 Windows 环境下会触发 `PermissionError`（WinError 5），表现为大量 ERROR 而非测试失败。

### 6.2 按改动类型选跑

| 改了什么 | 建议补跑 |
| --- | --- |
| 图表降级逻辑 | `python backend/scripts/demote_check.py`（strict / conservative 两次 POST 对比） |
| 删除链、数据留存 | `python backend/scripts/backup_check.py`（五张表 + 临时目录清空断言） |
| 接口字段、前端契约 | `python -m pytest backend/tests/test_api_contract.py -q` + `cd frontend; npm run typecheck` |
| 文档与接口是否同步 | `python backend/scripts/sync_check.py`（需后端已在 8000 端口运行） |

### 6.3 前端门禁

```powershell
cd frontend
npm run typecheck      # vue-tsc 类型检查
npm run build          # 生产构建
```

### 6.4 单篇论文命令行审查（不进页面）

```powershell
cd backend
python scripts/blind_test.py --doc ../samples/real/blind-003.docx          # 纯规则
python scripts/blind_test.py --doc ../samples/real/blind-003.docx --llm    # 含模型顾问（需 Key）
```

输出解析统计、逐条判定（含锚点段号）与 notes；适合快速核对某篇的判定结果。

## 7. 数据落在哪、怎么清

| 内容 | 位置 | 何时清除 |
| --- | --- | --- |
| 上传的 DOCX | `backend/data/tmp/<会话ID>/<随机名>.docx` | purge / 会话过期 / 启动清理 |
| 内嵌图片（供视觉识读） | `backend/data/tmp/<会话ID>/<上传件名>_media/` | 同上（随会话目录整体删除） |
| 解析结果、报告、追问历史 | `backend/data/app.db`（SQLite） | purge / 过期清理 / 重启即清 |

**手动清空**（相当于回到全新状态）：

```powershell
# 停止服务后执行
Remove-Item -Recurse -Force backend\data
```

下次启动会自动重建 `data/` 与数据库表。

> 页面上的「删除当前会话数据」按钮走的是 `POST /api/v1/sessions/purge`，会同时删除数据库记录与临时目录（含图片）。

## 8. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面能开但请求全 404 / 502 | 后端没起或端口不是 8000 | Vite 代理目标固定为 `http://127.0.0.1:8000`（见 [vite.config.mjs](file:///d:/Users/echo/Documents/2026-09-06/https-www-aicomp-cn-tracks-tracks/paper-method-review/frontend/vite.config.mjs)），按 §3.1 启动后端 |
| 启动报 `未识别到章节` 或清单加载失败 | 未在 `backend/` 目录内启动，`CHECKLIST_DIR=../checklists` 解析错 | 严格 `cd backend` 后再启动 |
| 启动日志出现 `env_key_conflict` | 宿主机环境变量里有旧 Key，与 `.env` 不一致 | 系统按 `.env` 生效，不影响使用；如需消除，清理该环境变量后重启 |
| `.env` 改了没生效 | 未重启后端 | 重启 uvicorn |
| 上传报 413 | 超过 `MAX_UPLOAD_MB`，或解压体积/压缩比/页数超限 | 调大配置或换小文件 |
| 上传 PDF 被拒 | 一期仅支持 DOCX（`PdfParser` 为占位实现） | 转换格式 |
| 模型相关结论全是「存疑」 | Key 未配置 / 调用失败 | 看后端日志 `llm_unavailable`；规则结果不受影响，属预期降级 |
| 报告打开提示「已清除」 | 会话超过 2 小时 TTL | 预期行为；重新上传审查，或临时调大 `SESSION_TTL_HOURS` |
| `pytest` 大量 ERROR 且都是临时目录 | Windows 临时目录权限问题 | 加 `--basetemp=../.pytest-tmp` |
| 前端 `npm run dev` 报端口占用 | 5173 已被占用 | 释放端口，或改 `vite.config.mjs` 的 `server.port`（同步改 `ALLOWED_ORIGINS`） |
| 视觉识读没触发 | 未启用模型顾问 / `LLM_VISION_ENABLED=false` / 文档无图片 | 勾选「启用模型顾问」并确认文档含图 |

## 9. 本地 vs 生产：差异一览

| 维度 | 本地（本手册） | 生产（另一本手册） |
| --- | --- | --- |
| 启动方式 | `uvicorn` + `vite dev` 两个进程 | `docker compose up -d --build` |
| 访问入口 | :5173（Vite 代理） | :443（前置 Nginx 终止 TLS） |
| `APP_ENV` | `dev` | `prod`（强制关 DEBUG/Docs） |
| Cookie `Secure` | 关（HTTP 可用） | 开（必须 HTTPS） |
| HSTS | 关闭 | 启用 |
| 数据卷 | `backend/data/` 本机目录 | `./data` 挂载卷 |
| 上线门禁 | 无需 | `deploy_gate.py` 必须返回 0 |
