## 1. TLS 证书 + HTTP→HTTPS 跳转 + 开启 HSTS —— ➖ 不适用（本地包不上公网）

本地包前后端端口只绑 `127.0.0.1`，客户端经本机回环访问，不经过网络传输层，无需 TLS。若日后对外 / 局域网 HTTPS 发布，见《附录》§A。

**已内置（无需动作）**：`frontend/nginx.conf` 已启用 `X-Content-Type-Options`、`X-Frame-Options DENY`、`Referrer-Policy`、`Permissions-Policy`、CSP（`connect-src 'self'`、`frame-ancestors 'none'`）；HSTS 已预留为注释项。
> 出向数据流（服务 → 模型）已默认走 `https://api.deepseek.com`（HTTPS/TLS，统一经 `LLMProvider`）。

## 2. 端口最小暴露（仅回环，DB/data 不暴露） —— ✅ 已内置

**已内置**
1. `docker-compose.yml`：后端 `127.0.0.1:8000`、前端 `127.0.0.1:8080`，均不绑定公网地址。
2. `data/`（SQLite 与临时目录）经命名卷挂载在容器内，不作为 nginx 静态目录，无法经 HTTP 访问。
3. 前端容器为唯一入口，`/api/` 反向代理到后端，后端不直接对外。

**运行方可选核对**
- 本机 `ss -lntp`（Windows 用 `netstat -ano`）确认仅 8080/8000 绑回环；
- 如需局域网内多人访问，请在**前置反代**上限制来源并启用 HTTPS（见附录 §A），不要把 8080 直接绑到 `0.0.0.0`。

## 3. 独立模型 Key（含在交付包内）+ 轮换 —— ✅ 已内置

**已内置**
1. 打包时把宿主机 `backend/.env`（含独立 `DEEPSEEK_API_KEY`）放入交付 tar 的 `backend/` 下；`backend/.dockerignore` 已排除 `.env`，故它**不进镜像层**（`docker history` / `docker inspect` 读不到），仅由 compose `env_file` 在容器启动时从宿主机读取 → 开箱即用、模型可用。
2. 包内不使用开发 Key（开发 Key 曾出现在聊天记录中，须先吊销）；请改用**新建的独立 Key**，可设额度、可随时吊销。

**运行方需做**
1. 轮换（建议每 90 天）：在服务商控制台新建 Key → 更新 `backend/.env` → `docker compose restart backend` → 吊销旧 Key。
2. 若把包转交他人：包内 `backend/.env` 携带 Key，请注意范围（改用独立 Key，或改成让对方自备）。
3. 重启后验证：`curl -s http://127.0.0.1:8000/api/v1/health`。

## 4. 删除传播（purge 覆盖五表 + 临时目录） —— ✅ 已内置

**已内置**
1. 正文仅在会话内暂存：原始 DOCX 落 `TEMP_DIR`（随机文件名），解析后的结构化正文入 SQLite `documents.ir_json`。
2. `POST /api/v1/sessions/purge` 与过期清理任务同时覆盖 `sessions/documents/reports/jobs/chat_messages` 五张表与临时目录；`backup_check.py` 可自证。
3. 运行期常驻清理任务按保留期回收过期会话与孤儿临时目录。

**运行方可选核对**
- 调用 purge 后确认五表无残留、临时目录不存在；
- 若需长期留档报告，见《附录》§B（加密备份与保留期）。

## 5. 日志轮转与保留 ≤30 天 —— ✅ 已内置

**已内置**
1. `docker-compose.yml` 的 `x-logging`：`json-file`、`max-size=10m`、`max-file=30`（约 300 MB 上限）。
2. 应用日志经 `core/logging.py` 的 `RedactionFilter` 脱敏，禁止记录正文 / 密钥。

**运行方可选核对**
- 抽查容器日志无正文 / 密钥；如需更短保留期可调小 `max-file`。

## 6. 健康检查（容器存活探针） —— ✅ 已内置

**已内置**
- backend：`GET /api/v1/health`；frontend：`GET /healthz`；均写入 compose `healthcheck`（interval 30s / timeout 5s / retries 3），`restart: unless-stopped` 自动拉起。

**运行方可选（告警）**
- 如需告警，见《附录》§C（5xx / 429 / 模型失败率 / 磁盘）。

## 7. 事件响应演练（密钥泄漏 / 被刷 / 误删） —— ➖ 不适用（不上公网）

本地包不对公网暴露、单机回环访问，密钥泄漏与被刷风险面极小。若在内网多人使用，建议至少演练：**密钥泄漏**（吊销 → 换 Key → 重启 → 核查日志）与**误删恢复**。

## 8. 镜像漏洞扫描（Trivy） —— ➖ 不适用（本地包不上公网）

本地单机、回环访问，无对外暴露面，故不作为交付阻塞项。CI 已包含依赖漏洞扫描（`pip-audit`、`npm audit`）。如仍希望自证供应链安全，可按《附录》§D 自行扫描。
